# 用界面配置、生成和保存一个工程

本例建立两个 App：`sensor` 发布感知帧，`display` 订阅完整感知帧。最后把配置保存成可交给同事、可继续维护的文件。

先完成 [环境准备](GETTING_STARTED.md)。以下命令在仓库根目录执行，Windows 将 `./amw` 换成 `.\amw.ps1`。

## 1. 启动并新建工程

```bash
./amw gui
```

在浏览器打开终端打印的网址，默认是 `http://127.0.0.1:8765`。初始页面加载仓库 demo；它不会自动找回上一次未保存的编辑。

在顶部工程栏点击“新建工程”，工程 ID 填 `vehicle_demo`。这是工程名称，不是 App 名，也不是消息类型。新工程会清空类型、App 和连接，并沿用当前编辑器中的网络与策略设置；因此稍后还应检查部署。

页面顶部的“当前工程”会显示 `vehicle_demo`，向下滚动时仍保持可见。浏览器标签也会显示工程名；有未保存修改时，标签名前有 `*`，工程名称旁显示“未保存更改”。新建、打开工程、编辑完整模型或撤销/重做后，名称都会同步更新。

“工程已载入”表示当前内容与本次加载时一致；“草稿已保存”表示与本次会话最近一次成功保存的内容一致。这些标记不等于校验或生成成功。保存失败不会消除未保存标记；如果保存过程中又做了编辑，后续更改仍会标为未保存。草稿按工程 ID 保存到 `out/editor/<工程ID>/`，本例为 `out/editor/vehicle_demo/`。工程 ID 改名后使用新目录，原目录保留；不同工程应使用不同 ID，避免仅大小写不同。

## 2. 导入消息类型

点击“导入类型 JSON”，选择仓库的 `examples/type-guide/perception.cmtypes.json`，检查预览后点击“应用”。左侧应出现 Category、Object、Frame 三个类型。点击类型会打开侧边详情面板，可逐级查看字段结构；搜索框可输入类型名、嵌套字段名、说明或单位。

它们的关系是：Frame 中有一个 Object 列表，Object 中有 Category 枚举。实际对外发送时选择 Frame 即可，嵌套类型也会被生成。自己编写文件的方法见 [JSON 类型指南](JSON_FORMAT.md)。

导入只是编辑步骤，完整检查在“校验”时进行。导入与已有类型同名且同版本的定义，会替换编辑器中的那份定义。

### 工作台布局与类型库

桌面布局左侧是固定高度的类型库，右侧是主工作区。类型列表独立滚动，搜索、导入和筛选始终保留在列表上方；导入数十或数百个类型不会把整张页面拉长。长名称在列表中省略，悬停查看完整名称，点击进入详情。窄窗口下类型库移到上方，仍保持独立滚动。

- 列表分为“用于消息输出”“其他结构体”“枚举”，可筛选全部、已用于输出、结构体或枚举。是否用于输出根据实际 App 输出引用判断，刚导入时不会根据文件顺序猜测主消息；通过其他结构体间接使用的类型仍列在“其他结构体”中。
- 类型详情显示字段结构、说明、直接依赖和直接引用它的类型，以及相关 App 输出。相关输出区分直接输出和嵌套使用。引用项可点击继续查看；通过“关闭”或 Escape 返回列表。
- 类型详情中的“编辑结构”“删除类型”保留原有校验与引用保护；原始 JSON 收在“查看类型 JSON”中，平时无需展开。
- 主工作区默认“应用配置”；点击“数据流图”查看连接，两种视图共享同一工程。左右方向键也可以切换工作区标签。切换、筛选和查看详情不修改模型，不增加撤销记录。
- “QoS / 默认策略 / 网络”打开独立配置窗口；下方“部署概览”按需展开查看各实例并进入其配置。
- 操作结果位于页面底部，状态与错误/警告直接显示，完整返回内容在“查看详细结果”中展开。新操作会清除旧详细结果，避免把旧结果当成当前结果。

顶部工程栏直接显示“新建工程”“打开工程”“导出工程包”，与当前工程名称和保存状态放在一起。“打开工程”接收导出的 `.amw.json` 工程包；仅导入类型时使用类型库的“导入类型 JSON”。保存、校验、生成和撤销/重做位于主工具栏，“编辑完整模型”位于独立的“高级工具”入口。类型库显示 0 项时，先清除搜索并选择“全部类型”，再判断是否需要导入。

## 3. 配置输出和输入

点击“添加 App”两次，依次输入 `sensor` 和 `display`。工具自动增加 `sensor_instance` 和 `display_instance` 两个默认部署实例。

在 sensor 卡片中点击“增加输出”，填写：

| 表单项 | 本例填什么 | 表示什么 |
|---|---|---|
| 输出消息名 | frame | 这条输出的业务名称。 |
| 数据类型 | 搜索 Frame，点击 perception.Frame @1.0.0 的结果 | 消息的完整结构；需明确选择，不默认选中任何类型。 |

直接点击“应用”，无需配置分组。新 App 会自动建立 `output` 输出分组，应看到 `输出 output.frame`。再次“增加输出”时自动沿用这个分组，消息可以使用相同或不同的数据类型。

在 display 卡片中点击“选择输入”：来源选 `sensor / output`，勾选 frame，直接点击“应用”。工具自动命名输入分组为 `sensor_output`，应看到 `输入 sensor_output.frame`。切换到“数据流图”后，可看到从 sensor 的 output 到 display 的 sensor_output 的箭头。

这里选择的是完整消息，不能只订阅 Frame 内部的 object_id。新增另一个接收 App 并执行同样操作，就能让多个 App 接收同一输出。

### 按需管理分组与修改订阅

通常一个输出分组就够用。一个 App 对外提供多个独立服务时，例如感知结果与运行诊断，可在“增加输出”中展开“高级：分组设置”，选择“新建输出分组…”并填写名称。已有多个输出分组时，窗口会展开设置并要求明确选择；也可以点击某个输出分组旁的“添加消息”，直接向该组追加。已有工程仅有一个输出分组时沿用原名称，不自动改成 output。

输入分组名根据来源自动填写，重名时追加编号；需要业务化命名时，可在高级设置中修改。更换来源会更新自动名称，已手工填写的名称会保留。同一 App 的输入、输出分组不能重名；不同 App 可以使用同样的名称。

在输入分组旁点击“编辑订阅”，勾选或取消该来源下的消息，点击“应用”。这会修改已有输入，不创建第二条连接；至少保留一条消息。需要全部移除时，在数据流向图中移除连接。编辑时也可以在高级设置中修改输入分组名；连接、各实例的绑定键和保留消息的 QoS 覆盖同步更新，取消订阅消息的专用覆盖会删除。各实例原有的具体来源保持不变。需要接入另一来源时，使用“选择输入”新增分组。

分组是模型中的逻辑服务端口，不是 UDP/TCP 端口号，也不提供权限或线程隔离。分组名和消息名参与生成接口命名，修改后需重新生成、编译并调整业务调用。名称使用字母开头的字母、数字、下划线，不能包含连续双下划线或使用保留字；完整约束由“校验”检查。

### 搜索并确认数据类型

“数据类型”是搜索框和结果列表，默认不选中任何类型。可输入类型短名称、完整名称、说明文字或结构体字段名，不区分大小写；空格分隔的多个关键词要求同时匹配。类型名匹配优先于说明和字段匹配。搜索为空时显示全部结构体，枚举不能直接作为消息输出。

例如导入[通用测试类型库](../tests/fixtures/sample-types.cmtypes.json)后，输入 `MESSAGE` 可找到 `sample.Message`；输入 `sample_id`，结果会包含直接拥有该字段的结构体和引用它的外层结构，并显示 `batch.items[].sample_id` 这样的匹配路径。`[]` 表示经过数组或列表，不是选取某个数组元素。

点击结果才能确认类型，即使只剩一个结果也不会自动选中。每条结果显示短名称、完整名称、版本和简短说明，避免同名或不同版本混淆。选中后展开“结构预览”，再逐级展开字段，查看字段类型、数组长度、嵌套结构、单位和说明。搜索字段只是帮助定位完整消息，最终发布的是选定结构体的完整内容。

修改搜索词会清除之前的选择；也可以点击“清除类型选择”重新查找。没有匹配项时尝试其他关键词，或先在类型库中定义类型。未选择时“应用”不可用，手工输入类型名称本身不会创建引用。键盘可从搜索框按上下箭头进入结果，用上下箭头、Home/End 移动，按 Enter 选择；Tab 也可访问结果按钮。重新打开输出窗口时不会记住上次选择。

`perception.` 是类型库定义的命名空间前缀，与分组无关，也不是强制要求；一个数据类型可以被多条消息复用。

### 怎样阅读和操作数据流向图

先点击主工作区的“数据流图”；继续添加输出或输入时切回“应用配置”。

- 每个方框是一个 App；蓝色端口表示输出，紫色端口表示输入，箭头从输出指向输入。尚未连接的 App 也会显示，便于检查遗漏的配置。
- 一条连线表示一组服务端口之间的逻辑连接，可能包含多种完整消息。点击连线或旁边的编号，下方显示完整的来源、目标、消息名称、类型和版本；选中的连接及两端 App 会高亮。长名称在节点中会省略，悬停可看完整名称。
- 点选连接后点击“移除连接”，同时移除对应 App 输入、部署绑定和该输入的消息策略覆盖；需要恢复时点“撤销”。不要把连线编号当成配置 ID，它只是当前图中的选择标记。
- “+ / −”调整缩放，“适应宽度”重新适配窗口；放大或图较大时，在画布内滚动。也可以用 Tab 选择连线、Enter 或空格打开详情。
- 图支持分支、多级连接、反馈回路和同一个 App 自订阅。回路会排列在同一列并使用折返箭头，不强行画成无环流程。较密集的图仍可能出现交叉线，可点选高亮后追踪方向。

这是**配置中的逻辑数据流**，不是实时通信监控，也不代表 DDS 已发现对方或数据正在传输。图的节点是 App 定义；同一个 App 的多个部署实例及具体来源仍需在部署配置中检查。

## 4. 检查部署与网络

点击“QoS / 默认策略 / 网络”。消息策略、实例与端点策略分配、Participant/Publisher/Subscriber 参数和网络设置均有结构化表单。每项开放参数都有默认值，只修改有需要的项；“恢复继承”撤销单个参数覆盖。完整步骤与支持范围见 [QoS 配置指南](QOS.md)。

第一次在同一开发机验证，可以保留示例的 Domain 37、空 interface_address、空 peers 和 UDP 配置。若与其他工程共用测试环境，应避免相同 Domain 和消息路由造成干扰。

重点检查：display_instance 的 sensor_output 应绑定到 sensor_instance 的 output。以后同一 App 部署为多个实例时，可通过“高级工具 → 编辑完整模型”调整实例和来源，不能只看消息类型是否相同。字段说明见 [JSON 指南第八节](JSON_FORMAT.md#8-类型文件工程文件和部署文件的关系)。

当前只实现 Fast DDS，页面中的 vsomeip 说明不是可用的协议选择项。

## 5. 校验、生成并找到结果

点击“校验”，看到“校验通过”后，再点击“生成 src-gen”。生成在后台执行，结果显示在页面底部的“操作结果”区域。

生成前先查看工程栏下方的完整“生成目录”。默认输出为 `out/delivery/<工程ID>/src-gen/`，本例是 `out/delivery/vehicle_demo/src-gen/`。确认根目录有 `vehicle_demo.amw.json`，并有 `generated/apps.hpp`、`generated/types.hpp`、`runtime/`、`dependencies/` 和根目录的 `CMakeLists.txt`。如果生成时继续编辑了模型，页面会提示生成结果已经落后于当前编辑内容，需要再次生成。

需要改位置时，点击“设置生成位置”（也可从“高级工具 → 生成位置设置”进入），填写运行 GUI 服务电脑上的绝对**根目录**，确认弹窗显示的生成路径和草稿路径后点“应用”。例如根目录 `/tmp/amw-delivery` 加工程 ID `vehicle_demo`，最终目录是 `/tmp/amw-delivery/vehicle_demo/src-gen`。输入留空或点击“恢复默认位置”后应用，恢复仓库默认目录。设置只保存在当前浏览器站点的本机偏好中，换浏览器/端口需重新设置，不随 `.amw.json` 导出，也不影响 CLI。只应用位置不会立即创建或移动文件。

非法工程 ID、相对根路径或工程目录符号链接会显示错误；实际目录无写权限、已有文件冲突等在生成时报告。修正位置后重试，不要删除清单来绕过保护。同一工程再次生成更新自己的产物；改名后旧目录保留。生成任务使用点击时的工程和位置，期间修改配置不会改变正在执行任务的目标。

src-gen 根目录的 `README.md` 提供手册入口，`guide/` 包含通用接入/API 手册及固定 demo 示例。交给 App 开发者时保留整个目录；手册不根据当前 App 改写，实际接口以生成头文件为准。

点击“取消生成”是提出取消请求，应等待任务退出。正常的失败或取消保留上一次成功输出；如果从未成功生成，目录可能尚不存在。

## 6. 保存与下次继续编辑

三个动作的作用不同：

| 操作 | 得到什么 | 下次怎么用 |
|---|---|---|
| 保存草稿 | out/editor/<工程ID> 下的 types.cmtypes.json、project.cm.json、deployment.json。 | 用 --project 指向其中的 project.cm.json。 |
| 工程栏 → 导出工程包 | 浏览器下载一个 .amw.json 文件，内含类型、逻辑工程和部署。 | 在工程栏点击“打开工程”，选择 .amw.json 文件。 |
| 生成 src-gen | out/delivery/<工程ID>/src-gen 下的代码、依赖和 <工程ID>.amw.json。 | 编译或通过“打开工程”载入根目录的 .amw.json；只包含该次成功生成时的配置。 |

只有生成包时，也可以直接恢复工程：

1. 在已启动的工作台点击“打开工程”。
2. 选择 `src-gen/vehicle_demo.amw.json`（实际文件名取决于工程 ID）。
3. 打开后继续编辑，保存草稿或将工程导出到 src-gen 之外，再重新生成。

这个文件与 `metadata/model.resolved.json` 内容一致，包含生成时的类型、App、连接、部署、网络和 QoS 覆盖；恢复工程只需这一个文件。`metadata/qos.effective.json` 包含补全默认值后的 QoS，`metadata/routes.json` 是实例路由，`config/logging.xml` 是日志启动配置，它们不是“打开工程”的入口。本机 SDK/生成器路径与浏览器生成位置偏好不随工程包保存。

包内 `.amw.json` 受生成清单保护，不要直接修改。需要手工编辑时先复制到包外；若已经手改包内文件，先保留改动副本，再恢复原文件或生成到新的空目录。旧版本生成包没有根目录 `.amw.json` 时，可先打开 `metadata/model.resolved.json`，正常重新生成后会自动补齐入口文件。生成成功后的后续编辑仍须另行保存或导出，包内快照不会自动更新。

浏览器刷新或关闭前先保存或导出。草稿保存不会强制校验；但启动 GUI 的 --project 和“打开工程”都会先校验，**尚未有效的草稿或工程包可能无法重新打开**，需要用文本编辑器修复后再加载。建议保存一个已通过校验的版本作为恢复点。

从本例已校验的 vehicle_demo 草稿继续：

```bash
./amw gui --project out/editor/vehicle_demo/project.cm.json
```

建议同一仓库目录只开一个编辑器。同一工程 ID 仍使用相同草稿和默认交付目录，不同端口不会隔离它们。旧版本的 `out/editor/project.cm.json` 可继续通过 --project 打开；下一次保存会写入按 ID 划分的新目录。旧草稿和旧 `out/delivery/editor/src-gen` 不自动迁移或删除。

## 7. 保存业务源配置

`out/` 用于可重新生成的产物，`local/` 用于个人业务配置与实验，二者都不随中间件仓库提交。校验并保存后，可将本例的三个源文件一起复制到本地业务目录（首次操作；已有文件时先确认是否需要更新）：

```bash
mkdir -p local/projects/vehicle
cp out/editor/vehicle_demo/types.cmtypes.json local/projects/vehicle/
cp out/editor/vehicle_demo/project.cm.json local/projects/vehicle/
cp out/editor/vehicle_demo/deployment.json local/projects/vehicle/
./amw validate --project local/projects/vehicle/project.cm.json
```

Windows 可使用 PowerShell 的 `New-Item -ItemType Directory -Force local/projects/vehicle` 和 `Copy-Item` 完成同样的复制。三个文件应一起保留，相对引用才能保持有效。需要长期保存或团队协作时，将这三个文件放入独立的业务仓库管理；local/ 只是忽略目录，不是备份。

以后的编辑和生成命令可以写为：

```bash
./amw gui --project local/projects/vehicle/project.cm.json
./amw generate --project local/projects/vehicle/project.cm.json --output out/delivery/vehicle/src-gen
```

注意：从 local/projects/vehicle 打开后，“保存草稿”仍写 out/editor/<工程ID>，不会回写业务源目录。修改后需重新校验，将这三个草稿文件同步到业务源目录；需要提交时，在业务仓库中审查和提交。否则 CLI 仍会使用旧的业务配置。

提交业务配置给同事之前至少检查类型文件、工程入口和部署文件都进入了业务仓库的版本管理，且对方有自己的本地工具路径配置。完整产物交付方式见 [接入指南](INTEGRATION.md)。

## 在界面直接定义消息结构

前提：编辑器已启动并载入项目。在“类型库”点击“新建消息类型”，填写类型 ID、版本，选择结构体或枚举。

- 结构体逐行添加字段，填写稳定编号和名称，选择基本类型、字符串、定长数组、有界列表或已有类型引用。数组/列表可继续选择元素结构；集合必须填写长度边界。单位和说明可选。
- 枚举每行填写一个成员名。建议先建立被引用的结构或枚举，再建立外层消息。
- 点击应用时由后端统一校验；重复编号/名称、非法边界或递归引用会报错，窗口保留，修改后可重试，失败不产生撤销记录。
- 点击已有类型，在侧边详情面板点击“编辑结构”修改字段。已有 ID/版本保持固定；需新版本时新建类型。修改影响所有引用者，生成前须重新校验并同步更新收发双方。
- “删除类型”会检查引用；“导入类型 JSON”和“打开工程”继续支持已有数据。

完成类型后添加 App、输出及完整消息输入，再点击“生成 src-gen”。成功结果明确显示交付目录，整目录交给每位 App 工程师；包内已有 CM、日志、时间与三平台 SDK。生成准备失败会保留上次成功包，详情见结果区。
