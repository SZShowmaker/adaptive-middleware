# CM 应用开发手册

适用中间件：Adaptive Middleware 0.2.x；手册修订：2.1（2026-10-14）。当前绑定为 Fast DDS 3.6.2.0，序列化依赖 Fast CDR 2.3.6，代码生成器为 Fast DDS-Gen 4.3.0。

这是一份面向各 App 开发人员的通用手册，说明如何集成和调用 CM 通信接口。**内容不随工程名、App 名或每次生成而改写。** 中间件的公共接口、行为或接入方式变化时，由维护者统一修订；代码生成时仅原样附带这份手册。

## 这份手册与当前生成包怎样配合

手册可以单独阅读，但不会替你列出某个工程的接口清单。请结合完整生成目录中的以下文件：

| 文件 | 用它查什么 |
|---|---|
| `generated/apps.hpp` | 本工程有哪些 App 类、发布成员和 `on_...` 回调注册函数。 |
| `generated/types.hpp` | 本工程可直接使用的结构体、枚举、字段与 C++ 类型。 |
| `metadata/model.resolved.json` | 生成时的源配置快照（省略的 QoS 默认值见有效策略快照）：App、部署实例、字段说明/单位/边界、策略和网络配置。 |
| `metadata/routes.json` | 各实例的端点键、DDS Topic、输入来源对应的消息路由及最终策略。 |
| `metadata/qos.effective.json` | 每个实例、端点的完整有效 QoS，以及默认值目录版本和警告。 |
| `generation-manifest.json` | 依赖和工具版本、模型摘要、各文件摘要，包括随包手册与示例。 |

**交付整个 src-gen 文件夹即可。** 公共运行库源码、三平台 DDS SDK、构建入口和本手册均在包内，不再需要另行交付中间件安装包。应用只需准备匹配的 C++17 工具链与 CMake。

## 先记住的使用约定

1. 业务通常只需包含 `apps.hpp`，使用 `amw_generated` 的类型和 App 类；无须自己创建 DDS Participant、DataWriter 或 DataReader。
2. 先构造 App，再注册全部已配置输入的回调，最后调用 `runtime.start()` 并检查结果。
3. `try_publish()` 成功表示本地队列接纳了消息，不能据此认为对方已经收到或处理完成。
4. 接收回调在中间件工作线程执行。不同订阅可能并发；业务共享状态需要自己同步。
5. 在外部控制线程停止 App；回调里需要停止时调用 `request_stop()`。不要在自己的回调中销毁 App。
6. 网络、路由和策略已经编译进代码。修改旁边的 JSON 文件不会改变已编译程序；应修改源配置、重新生成和编译。

## 示例的适用范围

[examples/publisher.cpp](examples/publisher.cpp) 和 [examples/subscriber.cpp](examples/subscriber.cpp) 是固定示例，使用中间件仓库自带的 **demo 契约**：`producer`、`consumer`、`demo.Frame`、`demo.Health`。它们不按生成包中的 App 自动变换名称，也不会自动加入业务构建。

如果拿到的是自定义契约，先按手册理解流程，再使用自己的类名、实例名、消息类型和端口名编写业务代码。示例中的字段值没有替你的业务定义坐标系、物理单位或算法语义。

## 维护规则

手册源文件在中间件仓库 `docs/app-guide/`。不要在生成包里维护自己的修改；下次生成会检查这些文件是否被手改，发现不一致会拒绝覆盖。需要项目补充说明时，放在生成目录之外。

消息字段或 App 名变化通常只需要更新配置和业务代码，不需要改通用手册。公共 API、生命周期、错误语义、构建或交付方式变化时，应修订手册版本并验证示例；重新生成后，各工程得到同一份新手册。旧生成包不会因仓库更新而被自动改写。

本版本借鉴 AUTOSAR AP 的 CM 职责；公开命名空间为 `amw::cm`，不声明 `ara::com` 源码兼容或完整 AP 符合性。当前以静态配置的发布订阅为主，尚无 RPC/Method、Field、动态选源、配置热加载或零拷贝保证。
